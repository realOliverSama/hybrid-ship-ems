## 与 NPU 形态的关键差异

1. **权重在二进制内**：`network_data.c` 直接编译入 ELF（Debug 于 SRAM .rodata；
   Release 于 XSPI2 NOR .rodata 段）——**TCN 不再需要 NOR 权重 hex**
   （`Binary/network-data-tcnq-v2.hex` 为 NPU 形态回退资产保留）；workclf 仍用
   NOR 0x70400000 不变。
2. **激活区由用户提供**：`stai_network_init` 后 `_activations=NULL`，run 前必须
   `stai_network_set_activations`（194,356 B 单段，对齐 ≥4；ems_infer_npu.c 静态
   数组绑定）。NPU 形态激活在 ATON 存储池内分配，无此步骤。
3. **运行同步**：`stai_network_run` 内联执行全部节点并返回 `STAI_SUCCESS`/错误码
   （mode 形参被忽略），无 `stai_ext_network_new_inference` / `run_continue` /
   `STAI_RUNNING` 状态——与 workclf（NPU 形态，ASYNC+ext 生命周期）不同。
4. **运行栈**：同一 `NetworkRuntime1201_CM55_GCC.a`（内含 Lite CPU 内核，如
   `forward_lite_pw_sssa8_ch` / `forward_lite_pad_constant`，nm 可证）；无 EC blobs /
   atonbuf，NPU IP 不参与 TCN 前向。
