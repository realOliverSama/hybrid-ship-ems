# Phase 2 报告：NN Predictive A-ECMS（预测通道对 oracle 增量的捕获率）

**日期**: 2026-08-26
**Spec**: `.specs/nn-predictive-ecms-phase2/`（Amendment v1.1 / v1.2）
**数据**: `results/ecms_phase2/runs_phase2.csv`（36 行）、`gate_result.json`
**Gate 判定**: **PARTIAL — nn_oracle_capture = 0.3704 < 0.50**

---

## 1. 研究问题回顾

Phase 1 已建立：oracle 前瞻（C3，全知未来）相对规则自适应（C2，仅 SOC 反馈）的增量为 **+1.63 pp**（S20：330.66→324.96 kg）。Phase 2 的问题（RQ4~6）：

- **RQ4**：用 NN 预测替代 oracle，能捕获这个增量的多少？
- **RQ5**：训练好的预测器对**未见过的新航次**泛化如何？
- **RQ6**：该预测器的部署预算（参数/内存/时延）能否落进 STM32N6？

预测目标（设计决策 F2）：未来 300 s 能量需求 Ê_H(t) = Σ P_demand(t+1..t+300)/3600 [kWh]，经 SOC_ref 前瞻通道（Phase 1 law=6 v2 同款）驱动实时控制器（C4，law=7）。

## 2. 数据与模型（T-201~T-203）

- **fleet-200**：随机航次生成器（7 类积木，seed=20260825）生成 200 条多样化航次，全剖面零拒绝零降额（Vdc_min=689.9 V）。S20/S01/S02/S07 **结构性隔离**，不进任何 split。
- **数据集**：77,586 窗口，输入 302 维（P_demand 300 s 历史 + v_ship + accel），航次级 split **140/30/30**；归一化 fit-on-train（y_mean=33.586，y_std=17.869 kWh）；泄漏检查全过（窗口不跨航次、split 互斥、首尾裁剪）。
- **选模**：MLP 302-128-64-1（47,105 参数）击败 LSTM 对照与 MLP 变体网格（6 组全记录，test 集零参与）。
  - N=80 探索批：val RMSE 10.166 kWh；**N=200 定稿批：val RMSE 9.303 kWh（MAE 5.736）**——数据规模红利 +8.5%。
  - 低估频率 under_freq=0.426（42.6% 时刻低估未来能量需求）；R²≈0.73（相对 y_std 17.87）。

## 3. Simulink 集成（T-204）：内联失败 → extrinsic 兜底

**原方案**（MLP 前向内联进 MATLAB Function 块）触发 Stateflow EML 解析失败（`Stateflow:cdr:ErrorsParsingEmlFcn`）。系统性攻坚排除了代码语法、图对象、接线、参数值、转置形式、尺寸声明（证据链存档于 `项目开发进展.md` 2026-08-25 晚条目），根因未定位。

**主 Agent 裁决启用 Amendment v1.2 兜底**：NN 前向改 `coder.extrinsic` 调用 `ecms2.nn_predict_ehat(t, P_load, v_ship)`（MATLAB 函数，persistent 环形缓冲 + 惰性权重加载 + t 驱动仿真间重置）。损失分析：**科学上零损失**（C4/C3/C2 消融语义不变）；工程上仅 1 Hz × ~0.9 ms 解释器开销（T-103 拒绝 extrinsic 的 100 Hz 场景不适用）；且 extrinsic 边界恰好对应 Phase 3 的 NPU 推理 / MCU 控制分工。

**验证链全过**：build law 0~7 全编译；10b smoke 3/3；S01 回归逐位一致；**T1 函数 vs Python max|Δ|=1.2e-14**；T2 mat 缺失回退逐位 ≡ law=6(ê=0)；T3 S01 闭环合理（SOC_end=0.6145，零降额）。

## 4. 主矩阵结果（T-205）

S20 复合航次（fuel_corr，kg；SOC₀=0.60，k_eq=0.4774）：

| 控制器 | fuel_corr | 相对 C0 节油 | 备注 |
|---|---|---|---|
| C0 规则基线 | 349.002 | — | Phase 1 复用 |
| C2 A-ECMS（规则） | 330.662 | 5.26% | Phase 1 复用 |
| **C4 NN-A-ECMS** | **328.549** | **5.86%** | 本阶段新跑 |
| C3 oracle-A-ECMS | 324.957 | 6.89% | Phase 1 复用（上界参照） |
| DP 全局最优 | 315.83 | 9.51% | Phase 0 物理上界 |

**nn_oracle_capture = (330.662−328.549)/(330.662−324.957) = 0.3704 → PARTIAL**

- C4 相对 C2 的增量：**+0.60 pp**（5.26%→5.86%），捕获 oracle 增量（+1.63 pp）的 37%，未达 ≥50% 合格线。
- 全矩阵零降额、SOC_end 全部落在 [0.60, 0.604]（C4 S20 = 0.6006）。
- 逐场景 capture：S02=+1.05（小样本噪声，不解读）、S01=−0.36、S07=−26.3（**失败模式，见 §6**）。S20 是唯一设计判定指标。

## 5. 泛化（RQ5）：留出 10 航次一次性测试

C4 vs C2 节油差分布（每航次 (fuel_C2−fuel_C4)/fuel_C2×100）：

- **median = −0.232%，mean = −0.096%，min = −1.060%，max = +1.207%，4/10 为正**。

**诚实结论：C4 在留出航次上平均不优于 C2。** 预测收益集中于 S20 这类长时结构化复合航次；对生成器分布内的一般航次，以当前预测精度（RMSE 9.3 kWh ≈ 归一化 σ≈0.45）经低增益通道（K_S=0.01）注入后，平均效应为中性。

## 6. 失败模式分析

1. **S07（桥区操纵）C4 恶化 1.2 kg**：该场景长时低功率段 + 突发操纵，NN 按平均能量预测导致 SOC_ref 系统性偏移方向错误。Phase 3 若携带 C4，需对该模式做场景分类门控或下限保护。
2. **低估偏向**（under_freq=0.426）：预测偏保守 → ê 偏负 → SOC_ref_eff 偏低 → 放电偏多。在 S20 上恰好有利（低负荷窗口放电被事后验证正确），在 S07 上有害。**收益方向依赖航次结构，这是 capture<50% 的深层原因**。
3. **预测精度天花板**：R²≈0.73 意味着约 27% 的未来能量方差不可由历史 300 s 窗口解释（浪、流的随机分量）。进一步提高 capture 需要引入航次计划类特征（未来速度计划、航段类型），超出当前"纯历史外推"设计范围。

## 7. 部署预算（RQ6）：STM32N6 可行性

| 项 | 数值 | 预算 | 结论 |
|---|---|---|---|
| 参数量 | 47,105 | — | 小 |
| 权重存储 fp32 / int8 | 184 KB / ~47 KB | XSPI NOR 充裕 | ✅ |
| 激活 RAM | <4 KB | SRAM 充裕 | ✅ |
| 单次推理 | 0.93 ms（TF-CPU 实测）/ <0.01 ms（NPU 量级） | 1 Hz 更新 → 占空 <0.1% | ✅ |
| 输入装配 | 300×4 B 环形缓冲 + 3 次 GEMV | MCU 侧 trivial | ✅ |

**RQ6 答案：部署预算完全满足，且余量巨大。** Phase 3 的部署形态与仿真架构同构（NPU 推理 = extrinsic 边界；MCU 控制 = law=6 内核）。

## 10. 结论与决策点（PARTIAL 判定，design §6 属用户决策）

**RQ4**：预测通道捕获 oracle 增量的 **37%**（S20：+0.60 pp，节油 5.26%→5.86%），**部分有效，未达 ≥50% 合格线**。
**RQ5**：留出航次泛化**中性**（median −0.23%）——收益依赖航次结构，不是普遍增益。
**RQ6**：部署预算**完全满足**。

**主 Agent 分析与建议**：

- 这是一个**有价值的边界结果**：纯历史外推 + 保守低增益通道，在结构化长航次上有真实收益（0.6 pp），但一般化收益为零。作为论文结论完全成立且诚实（"预测通道的价值取决于航次可预测性"）。
- C4 从未显著劣化 S20，但 S07 模式存在 −1.2 kg 级回退，**部署前需要失败模式门控**。
- 三个选项：
  - **(a) 带 C4 进 Phase 3**：C2 为主、C4 为实验对照一同部署，边缘实测给出最终答案；部署成本极小。——主 Agent 倾向此项。
  - **(b) 先提升 NN 再裁决**：加入航次计划特征（未来速度计划/航段类型）后可预期 capture 显著提升，但超出当前 spec 范围，需新 Phase 2.5。
  - **(c) 以 C2 收束**：Phase 1 的 5.26% 已是强结果，预测通道作为"探索性负结果"写入论文。
